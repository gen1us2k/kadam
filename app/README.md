# Kyrgyz 80/20 — веб-приложение

Приложение-путь изучения кыргызского. Построено на [Astro](https://astro.build) + React-остров.

## Принцип

Уроки живут внутри приложения: **`src/content/steps/step-NN.md`** — единственный источник
контента шагов. Разговорник и словарь читаются из корня репозитория (`../phrases.md`,
`../anki/kyrgyz-frequency.csv`) без дублирования. Уроки разбиваются на темы и встраиваются
внутрь шагов пути; недельно-дневной каркас («неделя N», «дни…», цели недели, мета-секции)
отбрасывается при сборке.

## Команды

```bash
npm install
npm run serve     # собрать dist и поднять сервер: http://localhost:4321 (сайт + API)
npm run dev       # http://localhost:4322 — HMR (нужен запущенный сервер для /api)
npm run build     # статическая сборка в ./dist
npm test          # серверные (ctc/static/tts) + клиентские проверки
```

## Модель пути

`lessons.ts` режет каждый шаг по `##`-темам, выкидывает мета-секции (Лексика/Задания/Чеклист),
чистит заголовки от «недели/дни». `index.astro` рендерит markdown тем в HTML через `marked` и
передаёт шаги в `Journey`. Типы шагов: урок (инлайн-контент, в фонетических уроках — встроенные
🔊), фразы выживания (step-01, из ../phrases.md), слова/повторение/корпус (StudySession),
дриллы морфологии (после шагов 2/3/4, глагольные — после 5; идут **перед** сборкой
предложений: механика → композиция), сборка предложений SOV (шаги 2–7), чтение с
кликом-переводом (шаги 10–11), экзамен-веха (шаги 4 и 8).
Практика на письмо и слух: в зрелых карточках чередуются ввод, cloze и **диктант на слух**
(TTS проигрывает слово — надо вписать). После верного ответа опционально «Тяжело»/«Легко»
(полные грейды FSRS; по умолчанию — Good, лишних кликов нет).

Фичи сомкнуты в петли: слово из читалки можно отправить «→ в повторение» (появится первым
в следующей сессии); завершение набора дриллов/фраз само отмечает станцию пути пройденной;
сданный экзамен отмечает свой шаг и хранит лучший результат. Статистика ведёт историю дней:
тепловая карта активности (12 недель) и прогноз «при текущем темпе 1500 удержанных ≈ через
X нед.». Прогресс шагов слов/корпуса считается из FSRS-данных (авто-«пройдено» при 80%
удержанных); остальное — чекбокс. Всё состояние — localStorage.

## Дневной цикл и нагрузка

Главная = единый план на сегодня: баннер показывает `повторить N · новых M · дрилл+фраза`
и одну главную кнопку («Начать сессию», пока есть работа; иначе — «Пройти новый шаг»).
Нагрузка держится устойчивой: ввод новых слов притормаживается при накоплении повторений
(`adaptiveNewLimit`), упорно забываемые слова («пиявки», ≥8 промахов) выводятся из очереди и
показываются отдельно для разбора. Прогресс шага считается по **удержанию** (слово повторено
≥2 раз и всё ещё вероятно вспоминается — `retention()` через FSRS), а не по «показано один раз».
Новые слова вводятся `verified`-первыми; непроверенный перевод помечается в карточке.

## Что сознательно НЕ делали (YAGNI)

Ни аккаунтов, ни бэкенда, ни синхронизации: состояние (FSRS-карточки, стрик, прогресс пути)
живёт в localStorage.

## Озвучка (TTS на бэкенде)

Произношение синтезирует **бэкенд** (`server/`): Meta MMS (facebook/mms-tts-kir) в ONNX через
onnxruntime-node. Браузер (`lib/tts.ts`) просто дёргает `GET /api/tts?text=…`, получает WAV и
проигрывает — модель (~114 МБ) в браузер не грузится, а повторные слова берутся из HTTP-кеша.
Синтез-хелперы (`parseTokens`/`tokenize`/`encodeWav`) — `server/tts.ts`, покрыты `test-tts.ts`.
Кнопки — в карточках, дриллах, читалке и словаре. Google TTS не поддерживает кыргызский
(проверено, 400), Forvo не встраивается без платного API — отсюда собственный MMS.

Модель (`models/tts/model.onnx` + `tokens.txt`, ~114 МБ) гитигнорена. Источник —
willwade/mms-tts-multilingual-models-onnx (папка `kir`) на HuggingFace; положить оба файла в
`models/tts/`. После переноса TTS браузер вообще не тянет `onnxruntime-web` (ASR тоже на
бэкенде) — из `dist` ушли и модель, и ORT-wasm.

## Распознавание речи + проверка произношения (PoC)

Страница `/poc-speech` — прототип: запись с микрофона, распознавание кыргызской речи и оценка
произношения. Распознавание работает **на бэкенде** (`server/` — TypeScript, тот же стек:
node:http + onnxruntime-node, iarfmoose/wav2vec2-large-xlsr-kyrgyz в ONNX int8): браузер
записывает голос, чистит вход (mono + noiseSuppression/AGC, обрезка тишины — `lib/audio.ts`) и
шлёт маленький 16-кГц WAV (~64 КБ на фразу) сырым POST-body — модель (~338 МБ) в браузер больше
не грузится.

Оценка — по **CTC forced alignment** к целевой фразе: раз фраза известна, аудио выравнивается
(Viterbi) на ожидаемые звуки, и для каждой буквы берётся её акустическая уверенность
(Goodness-of-Pronunciation) → % + подсветка по буквам. Устойчивее нечёткого сравнения
транскрипта. CTC-математика — `server/ctc.ts`, залочена на эталонную фикстуру
(`scripts/ctc-fixture.json` ↔ `server/test-ctc.ts`).

Контракт эндпоинтов (`/api/asr/analyze`, `/api/tts`, `/api/health`) — [`server/API.md`](server/API.md).

Фронтенд (`src/`, Astro) и бэкенд (`server/`, node:http + onnxruntime-node) — **один проект**
с одним `package.json`. Запуск (один порт 4321, Node ≥23):

```
npm install
npm run serve        # собирает dist и стартует сервер: http://localhost:4321 — сайт + API
```

Для разработки — `npm run dev` (:4322 с HMR); он проксирует `/api` на сервер :4321, так что
сервер (`npm start`) тоже должен быть запущен. `npm test` гоняет серверные (ctc/static/tts) и клиентские
проверки; `npm run typecheck` — оба tsconfig. Веса модели гитигнорены (>100 МБ); регенерация ASR:

```
python3 -m venv .venv && source .venv/bin/activate
pip install "torch==2.8.0" "transformers==4.57.6" "onnx==1.19.1" "onnxruntime==1.19.2"
python scripts/export-asr.py   # пишет models/{model.onnx, vocab.json, asr-meta.json}
```
